# Azw — source register

This is the technical register for the text-matching corpus. The authoritative machine-readable
record is `data/corpus/manifest.json`; generated counts and exceptional ids are in
`data/corpus/build-report.json`; approvals and holds are in `data/review/`.

**Corpus version:** `p2-e2bfaf5a3ad2`
**Searched collections:** `quran`, `bukhari`, `muslim`

The Unlicense does not require attribution; Azw credits the repository nevertheless. The repository
does not state which printed edition or upstream site the Arabic text was digitized from.

**Bukhari numbering.** `id = bukhari:<hadithnumber>`. `citation.number` is the integer part of
`hadithnumber`; 26 decimal source entries retain their full value in `citation.subNumber` and remain
pending.

**Muslim numbering.** `id = muslim:<hadithnumber>` uses the source's internal running number.
`citation.number` is the integer part of `arabicnumber` (Fuad Abd al-Baqi), with the full value in
`citation.subNumber`. Records without `arabicnumber` have `citation.number = null`, no grade and
remain pending.

**Grade policy.** A reviewed Sahihayn record carries `{ text: "صحيح", by: <collection>, sourceRef }`
as an attributed collection grade. The tool and model do not grade it. Every pending record carries
no grade (D-2, D-5).

## 3. Text handling

- Raw files are never edited.
- `exactText` reproduces the source. The only build change is removing leading U+FEFF characters
  from Quran ayat: 6,125 characters across 6,124 ayat.
- Quran pause, hizb and sajdah signs remain in `exactText`; hadith punctuation, direction marks and
  braces remain as supplied.
- `searchText` is normalized for retrieval and never displayed.
- Mushaf 2 creates one Uthmani search variant per ayah and never changes the display record.
- `data/aliases/quran-spelling-variants.json` contains 66 owner-approved forms, each restricted to
  its listed ayat. The list is not a general spelling fold.
- `matnText` exists only where a direct quoted saying can be separated as a verbatim substring. It
  is a review aid, not a separate production matching layer.

## 4. Integrity checks

### Raw provenance

- Both hadith files are byte-identical to commit `df57907`:
  - Bukhari SHA-256 `f887d8724f75fb6e1d5d29342a173af5346ad9b933173c85e6e3cb570063ea33`.
  - Muslim SHA-256 `2cb296f3455ff8a3da9f6a0ca3de75da675788b2fb446ad316df297838e48217`.
- The Quranpedia manifest versions and sizes agreed with the live manifest when checked.
- Each served Quran `.gz` decompresses byte-for-byte to the tracked JSON.

### Quranpedia checksum exception

The SHA-256 values published for the compressed mushaf 1 and mushaf 2 files do not match the files
served, although their byte sizes match and their decompressed contents equal the tracked JSON. The
cause is unknown. D-15 accepted the decompressed JSON as the integrity anchor after all 6,236 ayat
matched Tanzil's simple text letter-for-letter once diacritics and marks were removed. The project
does not claim that the compressed checksums passed.

### Quran spelling and Uthmani measurements

Removing diacritics bridges most display spellings but not forms such as «رحمت»، «رءوف»، «مسئولا»
and «مائة». D-9 selected the ayah-bound everyday list plus mushaf 2 as a search-only variant; no
global normalization rule was added. D-13 narrowed when an Uthmani hit may count as the same
spelling. All 6,236 whole ayat pasted from mushaf 2 then ended `MATCH` while ordinary misspellings
did not gain that path.

## 5. Hadith sample verification

### Dorar

[Dorar](https://dorar.net) is a verification source only, never the matching corpus or a runtime
dependency. Its public keyword API and book-filtered result pages were used under Dorar's stated
all-rights-reserved terms. Full responses are cached only in gitignored
`data/raw/dorar-cache/`; tracked evidence contains short grade lines or differing words.

With fixed samples of eligible records:

| Collection | Sample | Confirmed by number and ordered matn words |
|---|---:|---:|
| Bukhari | 30 | 30 |
| Muslim | 30 | 30 |

“Confirmed” required the same collection and number and at least 80% of the sampled matn words in
order. It did not mean full character equality.

### Word-level sample and second editions

Twelve records per collection were compared word by word with Dorar's book text. All numbers agreed.
The flagged records were then checked against digital editions on Shamela:

- `bukhari:2075` has six trailing words absent from both Dorar's book text and the Sultanate edition;
  it remains pending (D-14).
- `bukhari:2819` opens as a suspended report and Dorar marks it «[معلق]»; it remains pending without
  a grade (D-5).
- Five Muslim records agree word-for-word with the Turkish edition and were approved individually;
  their evidence is in `data/review/reviewed.json`.

These checks use digital copies, not physical printed volumes. The collection approval remains a
sample-based review.

## 7. Known source limits

- No qualified specialist has reviewed the complete corpus or the evaluation labels.
- The hadith repository does not identify its printed Arabic edition.
- Muslim has 148 records without a citation number; 71 Abd al-Baqi numbers have no usable record in
  this corpus. `NOT_FOUND` therefore never claims absence from Sahih Muslim itself.
- Nine Bukhari and 203 Muslim source entries are empty and absent from the corpus.
- The 81 ayat where the two Quranpedia mushafs differ in letters other than ا، و، ي and ء were not
  read manually one by one; their ids are in `build-report.json`.
- «متفق عليه» is checked through the wording present in both corpus copies; the data does not encode
  scholarly identity between differently worded narrations.

## 8. Reproducing checks

```bash
npm run verify:corpus
npm run verify:raw       # networked; the two documented Quran .gz checksum checks remain failures
npm run verify:dorar     # networked; subject to Dorar availability and terms
npm run probe:quran-spelling
```

The server independently validates corpus schemas, counts and file checksums on load.
