# عَزْو

> «انقل النص كما ورد، ومن حيث ورد.»

عَزْو تطبيق ويب عربي، موجّه لكاتب المحتوى الدعوي. يستخرج الآيات والنصوص المنسوبة إلى النبي ﷺ من المسودة، ويقارن اللفظ والمرجع بالمصادر المغطاة، ثم يعرض نص المصدر ومرجعه والفروق على مستوى الكلمات.

لا يثبت عَزْو صحة النص بإطلاق، ولا يفسّر القرآن، ولا يحكم على حديث، ولا يصدر فتوى. النموذج اللغوي يساعد في الاستخراج وشرح الفروق فقط؛ أما البحث والحالة النهائية فهما بقواعد برمجية حتمية مبنية على سجلات المصادر.

## النطاق الحالي

- القرآن الكريم: مصحف حفص من Quranpedia.net، مع نسخة بحث عثمانية لا تُعرض ولا يُستشهد بها.
- صحيح البخاري وصحيح مسلم: من `fawazahmed0/hadith-api` بالإصدار المثبت في سجل المصادر.
- الحالات: «مطابق لنص المصدر»، «مختلف في اللفظ أو المرجع»، «لم يُتحقق منه ضمن المصادر المتاحة»، «يحتاج مراجعة مختص».
- المسودات لا تُخزّن ولا يُسجّل نصها. يوضح [إشعار الخصوصية](docs/PRIVACY.md) ما يُرسل إلى مزوّد النموذج وما يبقى في الخادم.

التطبيق الحالي ويب متجاوب للجوال. ملفات التثبيت كـPWA وعامل الخدمة ليست مبنية بعد، فلا يصف المستودع النسخة الحالية بأنها تطبيق قابل للتثبيت.

## المتطلبات

- Node.js `20.9.0` أو أحدث، وnpm.
- حساب ومشروع في OpenAI مع رصيد أو فوترة مفعّلة، وصلاحية استخدام النموذج `gpt-5.6-luna`.
- مفتاح API يُنشأ من [لوحة مفاتيح OpenAI](https://platform.openai.com/api-keys). توصي [وثائق OpenAI الرسمية](https://developers.openai.com/api/docs/quickstart) بحفظه في متغير بيئة، وعدم وضعه في الشيفرة أو المستودع.
- اتصال بالإنترنت لتثبيت الحزم، وتنزيل الخطوط وقت البناء، واستدعاء OpenAI.

## التشغيل محلياً

```bash
npm ci
cp .env.example .env
npm run dev
```

في PowerShell استبدل أمر النسخ بـ:

```powershell
Copy-Item .env.example .env
```

املأ `LLM_API_KEY` في `.env`، ثم افتح <http://localhost:3000>. للتحقق من تحميل البيانات والإعداد:

```text
GET http://localhost:3000/api/v1/health
```

لا ترفع `.env` إلى Git. `.gitignore` يستبعد ملفات البيئة ما عدا المثال الخالي من الأسرار.

### متغيرات البيئة

| المتغير | القيمة أو الغرض |
|---|---|
| `LLM_PROVIDER` | مطلوب للتشغيل المدعوم؛ القيمة الحالية `openai` |
| `LLM_MODEL` | مطلوب؛ النموذج الذي قيس به المشروع هو `gpt-5.6-luna` |
| `LLM_API_KEY` | مطلوب؛ مفتاح مشروع OpenAI، من جهة الخادم فقط |
| `LLM_TIMEOUT_MS` | مهلة كل مرحلة تعتمد على النموذج؛ الافتراضي `15000` |
| `LLM_REASONING_EFFORT` | استخدم `none` لإعادة إنتاج إعداد التقييم المنشور |
| `CORS_ALLOWLIST` | أصول إضافية مفصولة بفواصل؛ الفارغ يعني الطلبات من الأصل نفسه فقط |
| `MAX_DRAFT_CHARS` | أقصى طول للمسودة؛ الافتراضي `12000` |
| `RATE_LIMIT_PER_MIN` | الحد لكل عميل في الدقيقة؛ الافتراضي `10` |

إعداد OpenAI مطلوب للمسار الكامل. إذا تعذّر اتصال المزوّد أو انتهت المهلة أثناء الطلب، ينتقل النظام بأمان إلى المستخرج القاعدي ويظهر التحذير `LLM_UNAVAILABLE_REGEX_ONLY`؛ هذا مسار مقاومة أعطال، وليس بديلاً عن إعداد المفتاح.

## أوامر المشروع

```bash
npm run dev              # خادم التطوير
npm run build            # بناء نسخة الإنتاج
npm start                # تشغيل نسخة الإنتاج بعد البناء
npm test                 # الاختبارات الآلية
npm run lint             # ESLint
npm run typecheck        # TypeScript دون توليد ملفات
npm run verify:corpus    # سلامة ملفات المطابقة وبصماتها
npm run check:cases      # سلامة حالات التقييم وربطها بالبيانات
npm run eval             # تشغيل التقييم؛ يستخدم OpenAI وقد يترتب عليه استهلاك مدفوع
npm run docs:api         # إعادة توليد وثيقة API من العقد البرمجي
```

لا يلزم بناء مجموعة البيانات للتشغيل العادي؛ النسخة المثبتة موجودة في `data/corpus`. إعادة بنائها عمل صيانة للمصدر وليست خطوة تثبيت.

## كيف يعمل

```text
المسودة
  → استخراج بالقواعد وبالنموذج بالتوازي
  → التحقق أن كل مقطع موجود حرفياً في المسودة
  → قراءة المراجع بقواعد ثابتة
  → البحث في القرآن والبخاري ومسلم
  → المطابقة والمحاذاة
  → تحديد الحالة بقواعد حتمية
  → فرق الكلمات والتصحيح الاختياري من نص المصدر
  → شرح مولّد ومقيّد لحالة الاختلاف فقط
```

العقد العام هو `POST /api/v1/review`، وتفاصيله في [وثيقة API](docs/API.md). يقرأ العميل المصادر التي بُحث فيها فعلياً من `coverage`؛ ولا يفترضها مسبقاً.

## حدود مهمة

- «لم يُتحقق منه ضمن المصادر المتاحة» لا يعني أن النص مكذوب أو غير موجود في كتاب آخر.
- السجلات الحديثية المعلّقة أو المتضررة أو غير المحسومة لا تنتج مطابقة.
- مراجعة الصحيحين قائمة على فحوص آلية وعيّنات، لا على مقابلة بشرية شاملة لكل سجل.
- حالات التقييم لم يراجعها مختص شرعي. الأرقام وحدودها موثقة معاً في [EVALUATION.md](docs/EVALUATION.md).
